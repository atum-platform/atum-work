# Native bridge T2 seam — 2026-11-24

Built locally, not live, on `feat/native-t3-bridge-t2-1124`, base `465ae1b95bfb5777516237da5d12c06bb8bc852f` (`feat/work-runtime-0.1.14`). No push, PR, CI, deployment, provider inference or nested agents.

Native inventory: `toolkits/atum/handlers.ts` already authenticates a live native provider/thread session, and `connector.ts` already reaches the private connector using its startup-pipe secret. This change extends that toolkit instead of injecting a new provider MCP configuration or another agent loop.

`agent_tools` provides list/call with authoritative cloud JSON schemas. Its arguments contain no agent/owner identity. The handler reuses live-caller checks, the native provider-session registry and thread lock. `boundRegistry.ts` reads a trusted grant for that exact thread/provider session, verifies owner DM or owner schedule, expiry, agent generation, Mac and consent revision, then forwards the tuple to `/tools` beside the existing `/ask`. It rereads the grant and live session before returning the response. Calls are finite and are not retried after an ambiguous network failure.

The trusted consent adapter must write an owner-private JSON array at `ATUM_WORK_BINDINGS_FILE` before starting provider sessions; this startup setting is removed from the inherited process environment. Each entry has `binding: {owner, agent, generation, mac, consent_revision}`, `actor`, `audience` (`owner_dm` or `owner_schedule`), `threadId`, `providerSessionId`, `providerInstanceId`, `expiresAt` (epoch milliseconds), and `enabled`. Atomic replacement supports revocation without server restart. This file is a local adapter seam, NOT a substitute for authenticating Atum identity/ownership at OAuth sign-in. Do not provision it from an untrusted request or model arguments. Full access still means the provider acts as the owner and can access owner files, as the plan explicitly accepts.

Cloud counterpart in atum-app: `agent/transports/bound_tools_mcp_server.py`, `BoundToolExport` and `connector_app`. Mount the ASGI route on the existing connector and supply a trusted exact caller-to-live-export resolver. No service starts automatically. Bindings must agree on both ends. The production consent adapter, route mount and forward OAuth admission are not wired by this checkpoint. They remain implementation work, not merely deployment acceptance.
